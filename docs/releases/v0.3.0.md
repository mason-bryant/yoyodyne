# v0.3.0

Released 2026-08-23, covering v0.2.0 to v0.3.0.

Five days in which the harness built most of what it needed to be watched rather
than driven. v0.2.0 could survive an interruption and let a newcomer start;
v0.3.0 can choose work on its own, report what it is doing into Slack, decide
what to do about work that stopped, and be installed and repaired by somebody
who has never seen it. It also closes a confirmed filesystem-escape class in the
writers that put agent output on disk.

## Key functionality

- **Repository-confinement remediation: the safe-write primitive and the gate**
  (`yoyodyne-ifd.136`) — the August 21 analysis confirmed that the artifact,
  invariant, and initialization writers could be walked outside the repository
  through symlinks, because lexical path containment is not containment. Every
  owned write now goes through one primitive that proves containment physically,
  at mutation time, with no way for a caller to opt out.
  Serves: Keep roles, policies, and provider selection configurable without
  making safety invariants optional.
- **`yoyo doctor`: every finding carries its remedy as a runnable command**
  (`yoyodyne-ifd.125.1`) — it answers "can work actually run here", and answers
  it before anything is spent rather than at the point a run discovers it
  cannot. **`yoyo setup`** (`yoyodyne-ifd.125.3`) walks the whole path
  interactively, and is idempotent and resumable, so a half-finished setup is
  something to continue rather than to start again.
  Serves: A newcomer can go from the documented install to a working first run
  on their own repository using the readme alone.
- **Personas report to Slack, one thread per work item** — the design
  (`yoyodyne-ifd.68.1`), the notifier and the persona voice
  (`yoyodyne-ifd.68.2`), and the sink with a checked-in app manifest and setup
  documentation (`yoyodyne-ifd.68.3`). Conversation milestones — admissions,
  attributions, decisions — thread alongside run events (`yoyodyne-ifd.114`).
- **Blocked-run triage: the development manager's first workflow**
  (`yoyodyne-ifd.102`) — stopped work reaches the development manager as a
  docket (`yoyodyne-ifd.102.2`) instead of waiting for somebody to go looking,
  and each of its decisions spends a durable per-item budget
  (`yoyodyne-ifd.102.4`) rather than starting again at zero every run. Thresholds
  are validated configuration (`yoyodyne-ifd.102.3`), and a re-run is a fresh
  attempt against changed ground (`yoyodyne-ifd.102.6`).
- **Watch mode: `yoyo work` runs until told to stop** (`yoyodyne-ifd.119`) —
  the harness takes work from the top of the backlog on its own, and keeps
  taking it, rather than running one item and exiting.
- **Add scheduler and concurrent worktrees** (`yoyodyne-ifd.3`) — with two
  guards that stop it choosing badly: an epic with open execution children is
  not itself runnable (`yoyodyne-ifd.123`), and integration-adjacent siblings
  are ordered so same-epic work stops racing shared surfaces
  (`yoyodyne-ifd.133`).
- **See and control work the harness is running on its own**
  (`yoyodyne-ifd.26`) — the intake hold, and the rule that no item the operator
  did not name is claimed without reading it and recording why that item was
  chosen.
- **Move approval from each work item up to the goals** (`yoyodyne-ifd.25`) —
  approving twelve goals once, rather than approving every item that serves
  them, is what let admission flow at all.
- **A cheap, safe daily release** (`yoyodyne-ifd.145`) — one verb wrapping the
  tag, the build, and the checksums, gated on the adoption walkthrough and the
  checks. This tag is the first one it cut.
- **Add product artifact governance** (`yoyodyne-ifd.1`) — the brief, the goals,
  the designs, and the decision records carry identity and metadata, so
  downstream work can name one durably; Yoyodyne's own artifacts were seeded
  with it (`yoyodyne-ifd.1.9`).
- **Add configurable management roles and CLI UX** (`yoyodyne-ifd.4`) — the
  architect and development-manager roles exist as configured agents.
- **A top-level `operators` mapping** (`yoyodyne-ifd.113`) — a human binds the
  identifier namespaces they are known by, and authority attaches to the human
  rather than to any one of them.
- **License Yoyodyne under Apache 2.0** (`yoyodyne-dob`).

## Enhancements

- **Docs architecture: a readable README, focused documents, one link map** —
  the structure decided once (`yoyodyne-ifd.121.1`), executed against it
  (`yoyodyne-ifd.121.2`), and the first two extraction tranches landed
  (`yoyodyne-ifd.121.3`, `yoyodyne-ifd.121.4`).
- **Surface failed runs and their reasons through a `yoyo` verb**
  (`yoyodyne-ifd.90`) — `yoyo status` reads back what the runs themselves
  recorded, including, in as many words, a run that recorded no selection reason
  at all.
- **Post-merge sync hygiene goes to machinery** (`yoyodyne-ifd.103`) — settle
  and reconcile own catching a target branch up and retiring a consumed branch,
  and both refuse on evidence rather than on a record.
- **Gate developer diffs on protected paths, deterministically, before review**
  (`yoyodyne-ifd.98`), and teach the reviewer that an unbacked path grant is a
  finding (`yoyodyne-ifd.106`).
- **Config, run records, and observability carry an account alias and a
  configuration revision** (`yoyodyne-ifd.137`) — so a run made before there is
  a second provider account can still be attributed to the one it spent.
- **`yoyo init` configures the Dolt remote when a git remote exists**
  (`yoyodyne-ifd.104`).
- **Triage thresholds as validated configuration** (`yoyodyne-ifd.102.3`), a
  docket view that reads the ledger the guards enforce (`yoyodyne-ifd.134`), a
  rerun refused pre-flight that spends no budget (`yoyodyne-ifd.131`), and a
  carry-out refused for capacity that waits or hands off rather than failing
  (`yoyodyne-ifd.135`).
- **Reporting polish across the Slack stack** — run-started messages speak as
  the role that actually selected the run (`yoyodyne-ifd.68.5`), personas wear
  configurable avatars (`yoyodyne-ifd.68.6`), the sink paces catch-up and
  digests deep backlogs instead of flooding into suppression
  (`yoyodyne-ifd.68.8`), out-of-tokens reaches the channel at warning severity
  from every harness process (`yoyodyne-ifd.68.10`), an idle harness with ready
  work says so periodically and quietly (`yoyodyne-ifd.68.11`), speaker names
  carry the product (`yoyodyne-ifd.68.13`), a thread never opens on a bare id
  (`yoyodyne-ifd.68.16`), and thread headers carry the item's title rather than
  its slug (`yoyodyne-ifd.118`).
- **Transient terminal run deaths self-retry within a durable attempt budget**
  (`yoyodyne-ifd.101`) — a provider that dies mid-response is reissued in the
  same worktree and session rather than failing the run.
- **An unresolvable or oversized reference in item text is omitted with a stated
  omission** (`yoyodyne-ifd.124`) rather than failing pre-flight.
- **The development manager runs on Fable** (`yoyodyne-ifd.94`), per the
  recorded operator decision.
- **Scope team mode: what it promises, who counts as an operator, what v1
  supports** (`yoyodyne-ifd.82.1`).
- **Architect record-keeping** — the two design amendments the seeding exposed
  are recorded and proposals verified to persist (`yoyodyne-ifd.88`), drafting
  residue is out of the four decision records (`yoyodyne-ifd.86`), and the
  re-arm narrowing revision is transcribed to the reconciliation section
  (`yoyodyne-ifd.107`).
- **Architect review of the triage workflow's harness-facing design**
  (`yoyodyne-ifd.102.1`).

## Bug fixes

- **Fence worktree pruning** (`yoyodyne-ifd.73`) — git auto-maintenance could
  delete a worktree registration mid-creation and lose the run with it.
- **Retry the worktree listing that crosses a half-written creation**
  (`yoyodyne-ifd.80`) — the other half of the same race.
- **The backend refuses the roles `yoyodyne-ifd.4` delivered**
  (`yoyodyne-ifd.95`) — the architect and development-manager agents were
  configured and could not speak. An unknown role is now refused at
  configuration load, before any work is claimed (`yoyodyne-ifd.97`), rather
  than mid-run.
- **A proposal approved in `--message` chat never becomes an item**
  (`yoyodyne-ifd.120`) — the `y` decision did not complete, which had wedged
  admission entirely on 2026-08-20.
- **Decomposition validates a goal and then drops it** (`yoyodyne-ifd.108`) —
  work the development manager broke down lost the goal it was attributed to.
- **Reports are reachable only inside interactive chat** (`yoyodyne-ifd.70`) —
  and `--message` mode leaked slash commands to the persona.
- **An oversized reference fails the run** (`yoyodyne-ifd.116`) — it excerpts,
  or is omitted with a note, instead.
- **Attributions recorded earlier stopped counting as naming a goal**
  (`yoyodyne-ifd.122`) — diagnosed, with the witness that survives a careless
  notes rewrite.
