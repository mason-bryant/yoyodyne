# v0.6.0

Covering v0.5.0 to v0.6.0. The release date is the tag's.

This release is about runs that stall or die without anybody deciding they should. A run whose process vanished, a run paused on a usage limit past its deadline, a reader that stopped on a field it did not know, and a claim that trusted a status clear the tracker had not made are each now settled by the harness rather than left holding a slot until a person notices. Stalls resume in their own session, slow tracker reads are waited out, and an approved change stopped by the environment is resumed rather than rebuilt. Alongside those: spend is recorded as what each invocation cost rather than a session's running total, a release can be cut against a protected `main`, developer slots can prefer labelled work and pick a model by label, and the dashboard's needs-a-human section opens into cards.

- **A conversation or repair invocation's recorded cost is its own increment, never the provider session's running total: spend is re-derived, and every surface stops overstating it 4x to 9x** (`yoyodyne-ifd.432.10`)
  Serves: The operator can see what the harness spends on their behalf: provider-reported cost, per work item, per run, and in total.

  Resumed sessions report their running total, and each invocation was recorded with that total, so summing them counted the session again on every turn: the last 30 days read $37,804 against about $9,724 actually spent. - **Work items carry labels, and a developer slot can prefer a label: it pulls work with that label first and the rest only when none is ready** (`yoyodyne-ifd.388`)
  Serves: Keep roles, policies, and provider selection configurable without making safety invariants optional, and support multiple providers behind one adapter contract.

  Work items carry the tracker's labels, and a developer slot can be configured to prefer one or more of them: it pulls that label's ready work first and the rest of the backlog only when none is ready, so it never idles on an empty label. Slots with no preference leave labelled work to a preferring slot that is free, `yoyo status` names each slot's label, and the schedule report says when an item was passed over for another slot. Configuration chooses what a slot pulls and never widens what it may do.

- **A developer model chosen per item by label: a configured mapping applied when the run starts and recorded on the run** (`yoyodyne-ifd.421`)
  Serves: [spend-follows-the-work] Spend follows the work: the model, the context, and the number of provider calls a task costs are chosen for that task rather than for the role that does it, and running cost is visible and classified so the operator can see what each kind of work costs and decide what it should.

  A configured mapping from a label to a developer model, for example documentation and test-only items on a smaller model, is applied when a run starts and recorded on the run beside the resolved model. The first match in the mapping's order wins, an unmapped item takes the developer's configured model, and unknown labels or models are refused at load. The reviewer's model is not mappable.

- **Runs prove they can execute at minute zero, and submit to review only with execution evidence** (`yoyodyne-ifd.184`)
  Serves: Every change is reviewed against the intent it claims to serve, by a role that did not write it, before it is integrated.

A run hands its change to review only with a record of what it ran against it, and the reviewer sees that record.
